Open-BFME-2 GameSpy Peer SDK provenance (peer/)
===============================================

The record that governs this directory — the owner's permission statement,
the licence findings, the dating of game.dat's SDK snapshot and the list of
deltas against the carrier — is ../PROVENANCE.txt. Until 2026-10-08 this file
was a verbatim copy of that record's BFME 1 original; it now says only what
is specific to peer/.

What is here
------------
Reconstructions, not vendored text. The Area 51 carrier that supplies the
qr2/gp/ghttp/serverbrowsing/gstats modules ships no peer/ directory, so no
period peer text exists to vendor. The 68 .c files here are bodies
transcribed from the 2007 public SDK (nitrocaster/GameSpy, src/GameSpy/Peer/)
with local declarations standing in for the period headers (peer.h /
peerMain.h of the snapshot EA built are unavailable, and the 2007 ones drag in
the common/gsPlatform layer that did not exist then). Most TUs hold one or a
few functions each, split out so that each placement carries its own
evidence; each file's header block says what anchors it. The ten .cpp files
are this repository's own code (address-named helpers and dispatch
reconstructions), not SDK sources.

The identification is not a guess. game.dat carries peer's `callbackFuncs[]`
at 0x008E5DD0 (VA 0x00CE5DD0): 34 sixteen-byte rows {type, copy, free, call}
in ascending type order, closed by a {34, NULL, NULL, NULL} terminator —
exactly the shape, order and cardinality of piCallbackType
(PI_NUM_CALLBACK_TYPES == 34) and of the callbackFuncs[] initialiser in the
2007 file (peerCallbacks.c). All 102 callback targets reproduce their
complete source bodies with independently verified callees and named
imports. Other anchors: peerIsAutoMatching 0x006996E0, peerInitialize
0x00699730, and the AutoMatch strings (`ATM %s :%s` 0x008E6130, `UTM %s :%s`
0x008E613C) that the AutoMatch TUs here implement. Most placements were
re-placed from Open-BFME-1's reconstructions (the ledger notes name the BFME 1
donor where one was used); peerCallbacks.c's header keeps that BFME 1 history
and labels it as such.

Ledger (measured 2026-10-08, re-derive rather than quote):

    363 rows   40,029 bytes   all matched, no `vendored=` tag
    re-derive:  grep -c 'GameNetwork/GameSpy/peer/' reverse/functions.csv

Version
-------
Peer >= 2.02.22 (the nickname-check table at 0x008E60A0, 10-15-2004; AutoMatch
present); no upper bound from strings — nothing separates a Nov 2004 Peer from
a 2005 one. That the 2007 text reproduces these bytes says the functions did
not change between late 2004 and 2007; it does not date them. The 2007 text is
the donor, not the version retail linked.

Build flags
-----------
As ../PROVENANCE.txt: `/MD /DNDEBUG`, `__cdecl`, Win32 headers from
reference/shims/gamespy, each TU's `// cl:` line adding the pinned BFME 1
reference tree's GameSpy include directory.
