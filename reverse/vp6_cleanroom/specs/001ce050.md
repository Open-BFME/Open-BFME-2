# DeringBlockStrong_MMX

name: DeringBlockStrong_MMX
rva: 0x001CE050
size: 2596
ret_site: 0x001CEA73
convention: cdecl, 6 stack args, caller cleans (ebx-based frame with 16-byte aligned stack, 0x1B4-byte locals)
args: postproc instance pointer (unused) | source block pointer (bytes | one pixel of context is read on every side) | destination block pointer (bytes) | pitch (int) | block q index (uint) | quantiser scale table (uint32 pointer)
returns: none
callees: none
tables: 0x00DB7A28 sharpen modifier (64 x int32) | 0x00DB7FF0 four 16-bit 128 | 0x00DB8000 four 16-bit 64 | 0x00DB8010 eight bytes of 64 | 0x00DB8020 eight bytes of 32 | 0x00DB8030 eight bytes of 127 | 0x00DB8040 eight bytes of 128 | 0x00DB8050 eight bytes of 223
fields: none

## Behaviour

Strong de-ringing filter for one 8x8 block (MMX). Inputs: the strength value is the quantiser-scale table entry for the block's quality index (sixth and fifth arguments), and the sharpening value is the entry for the same quality index of the 64-entry int32 table at 0x00DB7A28 (values -12, -11, -10, -10, -9, -9, -9, -9, eight -6, eight -4, sixteen -2, twenty-four 0). The upper cap on a neighbour weight is the smaller of three times the strength value and 32 (the cap is realised with the byte constant 255 - 32 = 223 listed in the tables and saturating byte adds/subtracts), the lower cap is 0.

Neighbour weights: a 'vertical' weight is computed for each of the nine horizontal pixel boundaries of every column (between the row above the block and row 0, between successive rows, and between row 7 and the row below), and a 'horizontal' weight for each of the nine vertical boundaries of every row (one pixel left and one right of the block are read). A weight starts as 32 plus the strength value minus the absolute difference of the two pixels across the boundary, if that is below -64 it is replaced by the sharpening value, otherwise it is clamped to the range 0..cap. The weights are built in 16-bit lanes and stored in two stack tables.

Output: every destination pixel is a weighted blend of the source pixel with its four neighbours: each neighbour contributes its boundary weight times its value, the centre contributes (128 minus the four weights) times its value, 64 is added (16-bit 64s constant listed) and the total is shifted right 7 (logical shift on 16-bit lanes, 0x001CE379), then packed to bytes with unsigned saturation. Only the 8x8 block is written, the destination uses the same pitch as the source.

Row visibility and aliasing: both weight tables are completely built from the original neighbourhood before any output store. The output is then produced row by row, and each row's blend re-reads the pixel rows above, at and below it from the source pointer at that moment (row 0 store 0x001CE384, followed by row 1's neighbour loads 0x001CE391 and 0x001CE3AB, the same store-then-load pattern repeating for each later row). When the destination aliases the source (in-place filtering) the row above the current row has already been replaced by its filtered value when it is read as the upper neighbour, so results differ from a disjoint-buffer call. Check case (retail-emulated): pitch 32, a neighbourhood of 100 everywhere, a single 108 at block-relative (3,3), quality index 0, scale table entries all 10: with disjoint buffers pixel (4,3) becomes 102, with destination equal to source it becomes 100. Callers that need disjoint-buffer results must not alias the two pointers.

Processor state: the routine uses MMX instructions only. No emms is executed anywhere in the routine, so the MMX register state is left in use on return (the separately installed clear-state routine at 0x001D7620 is the caller's cleanup).
