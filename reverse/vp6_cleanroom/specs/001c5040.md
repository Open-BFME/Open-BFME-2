name: bitreadonly
rva: 0x001C5040
size: 47
ret_site: 0x001C506E (also 0x001C505B)
convention: custom register ABI: EAX = pointer to the raw bit reader (0x0 unread bits in the current word, 0x4 current 32-bit word, 0x8 pointer to the next unread byte), ESI = bit count, result in EAX
args: EAX, ESI only
returns: the next bits of the stream as an unsigned integer, without consuming them
callees: none
tables: none
fields: reader 0x0 unread bits, 0x4 current word, 0x8 next byte pointer

Behaviour:
Peeks ahead in a big-endian bit stream read most-significant bit first. The reader holds a 32-bit word of which only the low "unread" count of bits are still unconsumed. The result is the next (bit count) bits of the stream in order. When the unread count is at least the bit count, those bits come entirely from the word (0x001C5050..0x001C505B). Otherwise all unread bits of the word form the high part of the result and the following byte of the buffer (the byte at the next-byte pointer, 0x001C505C..0x001C506E) supplies the rest, so the supported bit count is at most the unread count plus 8. Neither the reader state nor the buffer pointer is modified. The callers use a count of 6.
