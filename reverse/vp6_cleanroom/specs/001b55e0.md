name: VP6_AllocateTmpBuffers
rva: 0x001B55E0
size: 179
ret_site: 0x001B5692 (last of two ret instructions, first at 0x001B567F)
convention: cdecl
args: [esp+4] pointer to PB_INSTANCE (retail decoder instance, 0x4954 bytes)
returns: int, 1 on success, 0 on any allocation failure
callees: 0x001B5530 VP6_DeleteTmpBuffers, 0x001B6400 duck_malloc(size, tag 0)
tables: none
fields: see VP6_DeleteTmpBuffers spec for the raw/aligned pairs

Behaviour:
First calls VP6_DeleteTmpBuffers on the instance. Then allocates four scratch buffers in this order, each with tag 0, storing the raw pointer and then the 32-byte-rounded pointer:
 1. 0xA0 bytes (32 plus 64 shorts): raw to field 0x274, aligned to 0x270 (reconstruction coefficient buffer).
 2. 0xA0 bytes: raw to 0x288, aligned to 0x284 (temporary data buffer).
 3. 0x120 bytes (32 plus 256): raw to 0x28C, aligned to 0x290 (loop-filtered block buffer).
 4. 0xA0 bytes: raw to 0x280, aligned to 0x27C (temporary reconstruction buffer).
If any allocation returns null the function calls VP6_DeleteTmpBuffers again and returns 0. Otherwise returns 1. The scale buffer (0x264/0x268) is not allocated here.
Memory goes through the duck-memory shim: allocate = 0x001B6400 (size, tag), free = 0x001B6410. Every aligned buffer is kept twice: the raw allocation pointer and the pointer rounded up to the next 32-byte boundary (add 31, clear low five bits).
