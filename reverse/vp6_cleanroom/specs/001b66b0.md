name: AllocatePostProcBuffers
rva: 0x001B66B0
size: 292
ret_site: 0x001B67D3 (also 0x001B67C3)
convention: cdecl
args: [esp+4] pointer to POSTPROC_INSTANCE (retail post-processor instance, 0xC8 bytes)
returns: int, 1 on success, 0 on failure
callees: 0x001B65F0 DeletePostProcBuffers, 0x001B6400 duck_malloc
tables: none
fields: 0x44 frame height (configuration), 0xB4 motion-vector border, 0x98 Y stride, 0x8C unit fragment count, plus the raw/aligned pairs listed in the DeletePostProcBuffers spec

Behaviour:
Calls DeletePostProcBuffers, then allocates in this order (tag 0, raw pointer then 32-byte-rounded pointer):
 1. Intermediate frame: 32 plus Y stride times (height plus twice the border) times 3 halved (unsigned). Raw 0xB8, aligned 0xBC.
 2. Filter bounding array: 0x820 bytes (32 plus 512 dwords). Raw 0xA0, aligned 0x34.
 3. Deblock bounding array: 0x820 bytes. Raw 0xA4, aligned 0x3C.
 4. Fragment Q index array: 32 plus 4 times unit fragments. Raw 0xA8, aligned 0x24.
 5. Fragment variance array: same size. Raw 0xAC, aligned 0x28.
 6. Fragment deblocking flag array: 32 plus unit fragments bytes. Raw 0xB0, aligned 0x2C.
On any null result, DeletePostProcBuffers is called and 0 returned. Otherwise 1.
Memory goes through the duck-memory shim: allocate = 0x001B6400 (size, tag), free = 0x001B6410. Every aligned buffer is kept twice: the raw allocation pointer and the pointer rounded up to the next 32-byte boundary (add 31, clear low five bits).
