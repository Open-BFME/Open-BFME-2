rva: 0x001C1AD0

convention: cdecl
args: [esp+4] instance (unused), [esp+8] source block pointer, [esp+0xC] destination block pointer, [esp+0x10] pitch, [esp+0x14] fragment Q index, [esp+0x18] pointer to a 64-dword quantizer scale table
returns: void
callees: none
tables: 0x00DB7A28 sharpen table, 64 signed dwords indexed by Q index (read at 0x001C1AE7): -12,-11,-10,-10,-9,-9,-9,-9, then -6 for indices 8..15, -4 for 16..23, -2 for 24..39, 0 for 40..63
fields: none (two local 16-bit arrays of 72 entries each hold the vertical and horizontal neighbour weights)

Behaviour:
Adaptive smoothing of an 8x8 block that damps ringing while preserving edges. Let Q be the scale-table entry for the Q index. The weight cap is 3 times Q, limited to 32 (0x001C1B11..0x001C1B23).
Neighbour weights. For every pair of vertically adjacent pixels spanning rows -1 through 8 of the block (nine pairs per column, eight columns) and every pair of horizontally adjacent pixels spanning columns -1 through 8 (nine pairs per row, eight rows), a weight is computed from the absolute difference between the two pixels: the weight is Q plus 32 minus that difference (0x001C1B7A..0x001C1B80). If this is below -64 the weight becomes the sharpen-table entry for the Q index (a non-positive value that sharpens across strong edges), otherwise it is clamped to 0 from below and to the cap from above (0x001C1B83..0x001C1B9E). The vertical weights are computed first for all nine rows, then the horizontal weights, both from the unmodified source.
Output. Each output pixel is a blend of the pixel with its four edge neighbours (above, below, left, right): each neighbour contributes its own weight (the vertical weight of the pair it forms with the pixel for above/below, the horizontal weight of the pair for left/right) times its value, the pixel itself contributes 128 minus the sum of the four weights, times its value, 64 is added, and the total is arithmetically shifted right 7 and clamped to 0..255. The block therefore reads a 10x10 neighbourhood (one pixel of border on every side, 0x001C1B65..0x001C1B6A and following) but writes only the 8x8 block.
Store order and aliasing: all eight outputs of a row are computed from the source into temporaries before any of them is stored (row stores at 0x001C2243..0x001C2284). When the destination aliases the source, a row's left/right neighbours are therefore unmodified, but the row above has already been overwritten when the next row is computed, and the neighbour weights were all computed from the original pixels beforehand.
