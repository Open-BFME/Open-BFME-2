name: VP6_ReadHuffTokens (EA per-block form of the Huffman token reader)
rva: 0x001C5310
size: 1661
ret_site: 0x001C598C (also 0x001C5566, 0x001C5900, 0x001C5979)
convention: cdecl
args: [esp+4] pointer to PB_INSTANCE (retail decoder instance), [esp+8] pointer to the block's 64 coefficients, [esp+0xC] plane (0 luma, 1 chroma)
returns: AL only: an end-of-block offset byte from the instance's table at field 0x5FC (see below), the caller zero-extends AL
callees: 0x001C4FE0 bitread (register form), 0x001C50B0 bitread1 (register form), the lookup-table token extraction of VP6_ExtractTokenN is inlined
tables: 0x00BD8B48 token minimum values, 12 dwords: 0,1,2,3,4,5,7,11,19,35,67,0 (read at 0x001C546E)
        0x00BD8B78 coefficient band map indexed by scan position (65 signed dwords, read at 0x001C5574): position 0 gives -1, 1 gives 0, 2..4 give 1, 5..10 give 2, and 11..64 give 3 (this map never selects bands 4 or 5)
fields: 0x190 raw bit reader, 0x4524 current DC run length (2 dwords by plane), 0x452C current first-AC run length (2 dwords by plane), 0xA20 DC trees (0x90 bytes per plane), 0x30FC DC lookup tables (0x80 per plane), 0x1A70 AC trees and 0x31FC AC lookup tables (ordered precedence, plane, band: 0x90 and 0x80 per table), 0x2FAC zero-run trees and 0x43FC zero-run lookups (2 bands), 0x57C merged scan order (64 bytes, scan position to the storage slot of the selected inverse transform, read at 0x001C58CE, produced together with the Huffman tables by the scan-order setup), 0x5FC end-of-block offset table (64 bytes, produced by BuildScanOrder 0x001BBA20)

Behaviour:
Huffman-coded variant of the token reader for one block. Coefficients are stored at the storage slot given directly by the merged scan order byte for the scan position (0x001C58CE..0x001C58D6), a slot in the input layout of the selected inverse transform rather than a natural raster position.
DC: if the plane's DC run counter is positive it is decremented and the DC is zero (precedence class 0). Otherwise a DC token is extracted. End of block finishes the block. A zero token reads a run length: 1 plus 2 bits, and if that gives 3 it gains 2 more bits, if it gives 4 then one bit selects either 11 plus 6 bits or 7 plus 2 bits, the run counter is set to the length minus 1. Other tokens take the minimum value, plus extra bits for categories (category token minus 4 bits for categories 1..5, 11 bits for category 6), then a sign bit, giving the first coefficient. The precedence class is 2 for magnitudes above 1, else 1.
AC: if the plane's first-AC run counter is positive it is decremented and the block ends. Otherwise, for scan positions from 1 while below 64: a token from the AC table for the precedence class, plane and the band of the scan position from the band map. Zero token: the zero-run table (band 1 for positions at or above 6) gives a run symbol. The zero token itself occupies the current scan position, and the run symbol gives the number of further positions skipped: a symbol below 8 advances the scan position by the symbol plus 1 in total (add at 0x001C5817 then the shared increment at 0x001C58E4), and symbol 8 reads 6 further bits and advances by 9 plus their value (0x001C5834 then 0x001C58E4). The precedence class becomes 0. Example: a zero token at scan position 5 with run symbol 0 leaves position 5 zero and the next token is read at position 6 with precedence class 0. Example: a zero token at position 10 with symbol 8 and extension 0 leaves positions 10..18 zero and continues at 19. A run that carries the position to 64 or beyond ends the block, and the returned byte is then read at (position minus 1) relative to the table base, which lies beyond the 64-entry table when the position exceeds 64 (well-formed streams do not overshoot). End of block: when at scan position 1 a run length (same encoding as the DC run) sets the first-AC run counter to the length minus 1, and the block ends. Other tokens: minimum value plus extra bits plus sign, stored at the selected-transform storage slot for the scan position (merged scan order byte), precedence class updated.
Return value: the byte returned is the end-of-block offset table entry at one below the scan position reached when decoding stopped (loads at 0x001C5559, 0x001C58F2, 0x001C596D, 0x001C597E): entry 63 when all 64 positions were consumed, entry 0 when the block ended right after the DC coefficient.
