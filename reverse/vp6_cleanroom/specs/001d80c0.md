## Behaviour

Notation used below: inputs of a 1-D transform are in0..in7, its outputs out0..out7, intermediate terms are named by role, multiplier constants by their retail value (M[c](v) = floor(v x c / 65536), see the multiplier notation paragraph), sat() = clamp to -32768..32767, wrap() = modulo 65536.
Storage layout (SSE2 path): transmission coefficient i is stored at storage index entry i of the table at 0x00DB7E28. That table is the transpose of the ordinary zig-zag map (its first non-DC entry is 8, not 1), so the stored block is the natural block transposed: stored row r (16 bytes at offset 16r) holds natural column r, and lane j of a stored row holds natural row j. The quantiser table uses the same storage order. Input, quantiser and output are accessed with aligned 128-bit loads/stores (movdqa, e.g. 0x001D80D4, 0x001D80DD, 0x001D80FA) and must therefore be 16-byte aligned.

Pass arrangement: the first pass combines the eight stored rows lane-wise (loads of stored rows 3, 1 and 7 at 0x001D8149, 0x001D8171, 0x001D818A), since stored row r is natural column r, the frequency index of that pass runs across registers (natural column index) while each lane is one natural row - the first pass is therefore the transform of the eight NATURAL ROWS, done for all eight rows in parallel. One 8x8 16-bit register transpose follows (unpack sequences from 0x001D82F5), after which stored row r holds natural row r, the second pass combines those registers lane-wise, i.e. transforms the eight natural columns in parallel, with the rounding constant (0x00DB8800 via paddsw at 0x001D8509, 0x001D8542, 0x001D8560, 0x001D8588) and the arithmetic shift right 4 (0x001D8519-0x001D85A2). The result is stored in natural raster order (row r at output byte offset 16r). Natural-row first, natural-column second, exactly one intervening transpose.

Dequantisation: each stored row is multiplied lane-wise by the corresponding quantiser row (low 16 bits, 0x001D80DD-0x001D8130) and written to the output block (0x001D80FA-0x001D8144) without reordering.

Value contract of one 1-D transform of eight 16-bit inputs in0..in7 (obtained by symbolic evaluation of the retail instruction stream, every intermediate is a 16-bit value, 'sat' means the result is clamped to -32768..32767, 'wrap' means it is reduced modulo 65536, the pairs are evaluated difference-first, i.e. a 'sum' is formed as the difference plus twice the second operand, which is why the sum has two saturation points):
- multiplier notation: M[c](v) is floor(v x c / 65536) for the seven retail constants c = 64277 (word 16 of the block at 0x00E22980, i.e. 0x00E229A0, SSE2 copy at 0x00DB8820), 60547 (0x00E229A8 / 0x00DB8830), 54491 (0x00E229B0 / 0x00DB8840), 46341 (0x00E229B8 / 0x00DB8850), 36410 (0x00E229C0 / 0x00DB8860), 25080 (0x00E229C8 / 0x00DB8870) and 12785 (0x00E229D0 / 0x00DB8880), it is realised as the signed high half of the 16x16 product with, for the five constants above 32767, a wrapping add of v (those constants are stored wrapped), M[46341] applied to a derived value is realised the same way (wrapping add-back) except where noted.
- odd pair sums and differences: oddSum17 = sat(M[64277](in1) + M[12785](in7)), oddDiff17 = sat(M[12785](in1) - M[64277](in7)), oddSum35 = sat(M[54491](in3) + M[36410](in5)), oddDiff35 = sat(M[54491](in5) - M[36410](in3)).
- oddDS = sat(oddSum17 - oddSum35), oddSS = sat(sat(oddSum35 + oddSum35) + oddDS), oddDM = sat(oddDiff17 - oddDiff35), oddSM = sat(sat(oddDiff35 + oddDiff35) + oddDM).
- rotated odd terms: rotS = M[46341](oddDS) and rotM = M[46341](oddDM), both with wrapping add-back.
- even terms: evenSum = sat(sat(in4 + in4) + sat(in0 - in4)), rotEvenSum = M[46341](evenSum) with wrapping add-back, evenDiff = sat(in0 - in4), rotEvenDiff = high half of (evenDiff x 46341) plus evenDiff, where this add-back is wrapping in this SSE2 routine (it is saturating in the MMX routines).
- pair26: pairSum26 = sat(M[25080](in6) + M[60547](in2)), pairDiff26 = sat(M[25080](in2) - M[60547](in6)).
- second stage: eA = sat(rotEvenSum - pairSum26), eB = sat(sat(pairSum26 + pairSum26) + eA), oA = sat(rotM - pairDiff26), oB = sat(sat(pairDiff26 + pairDiff26) + oA), fA = sat(rotEvenDiff - rotS), fB = sat(sat(rotS + rotS) + fA).
- first-pass outputs (stored as 16-bit, no rounding, no shift): out7 = sat(eB - oddSS), out0 = sat(sat(oddSS + oddSS) + out7), out2 = sat(fB - oB), out1 = sat(sat(oB + oB) + out2), out4 = sat(eA - oddSM), out3 = sat(sat(oddSM + oddSM) + out4), out6 = sat(fA - oA), out5 = sat(sat(oA + oA) + out6).
- second-pass outputs: the same four pairs, but 8 is added (saturating) to each pair's difference before the sum is derived from it, and both results are arithmetically shifted right by 4: out7 = sat(sat(eB - oddSS) + 8) shifted, out0 = sat(sat(oddSS + oddSS) + sat(sat(eB - oddSS) + 8)) shifted, likewise out2/out1 from fB and oB, out4/out3 from eA and oddSM, out6/out5 from fA and oA.

Supporting sites in this routine: odd products 0x001D815C-0x001D8176, saturating pair combinations 0x001D819B-0x001D82D0 (first pass) and 0x001D83E2-0x001D85A2 (second pass), wrapping even-difference add-back 0x001D8266 (first pass, the MMX routines saturate here).
