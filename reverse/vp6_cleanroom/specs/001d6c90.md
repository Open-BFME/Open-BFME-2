# FilterBlock1d_h_mmx

name: FilterBlock1d_h_mmx
rva: 0x001D6C90
size: 211
ret_site: 0x001D6D62
convention: cdecl, 7 stack args, caller cleans
args: source pointer (bytes) | output pointer (bytes) | source pixels per line (uint) | pixel step (uint, unused in retail) | output height (uint) | output width (uint, used as the output row pitch) | filter taps pointer (int16)
returns: none
callees: none
tables: 0x00DB81A0 eight 16-bit 64 (rounding)
fields: none

## Behaviour

Four-tap (bicubic) one-dimensional filter producing an 8-pixel-wide block of 'output height' rows. The taps pointer addresses four groups of eight identical int16 weights at byte offsets 0, 16, 32 and 48 (loaded at 0x001D6C98-0x001D6CA3), the four weights apply, in order, to the sample one position before the output position, the sample at the position, the one after and the one two after. For each output pixel the four weighted samples are summed in 16-bit lanes, the rounding constant 64 is added (saturating add from the table at 0x001D6CF3) and the sum is arithmetically shifted right 7 (0x001D6CFA), the result is packed to a byte with unsigned saturation. Horizontal: the four samples are the pixels at x-1, x, x+1, x+2 of the same source row. Source rows advance by 'source pixels per line', output rows advance by 'output width' bytes, exactly 8 pixels per row are produced regardless of 'output width'. The 'pixel step' argument is not read in retail. No MMX state clear is executed by this routine: it leaves the MMX register state in use on return (the separately installed clear-state routine at 0x001D7620 is the caller's cleanup).
