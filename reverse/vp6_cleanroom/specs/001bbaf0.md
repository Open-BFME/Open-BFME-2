name: BoolTreeToHuffCodes
rva: 0x001BBAF0
size: 336
ret_site: 0x001BBC3F
convention: cdecl
args: [esp+4] pointer to 11 branch probabilities (bytes, one per internal node), [esp+8] pointer to 12 output weights (dwords, one per token)
returns: void
callees: none
tables: none (all constants are immediates: the complement constant 255 and the shift by 8 after each product, e.g. 0x001BBB0E, 0x001BBB02)
fields: none

Behaviour:
Converts the probabilities of the 11-node binary token tree into a weight per token, where a token's weight approximates its probability out of 256. The tree (as observed from which probability bytes feed which output) is: node 0 separates the pair of end-of-block and zero (taken with the node's probability) from everything else (taken with 255 minus the probability). Node 1 separates end-of-block (probability side) from zero. Node 2 separates one from the larger values. Node 3 separates the small values two, three and four from the six category tokens. Node 4 separates two from three and four, and node 5 separates three from four. Node 6 separates categories 1 and 2 from categories 3 to 6, node 7 separates category 1 from 2, node 8 separates categories 3 and 4 from 5 and 6, node 9 separates 3 from 4, and node 10 separates 5 from 6. In every case the first-named side takes the node's probability byte and the other side takes 255 minus it.
A token's weight is the product of the branch values along its path from the root, evaluated root-first in unsigned 32-bit arithmetic, where after every multiplication the running product is shifted right by 8 (so each intermediate stays below 256). The outputs are stored at dword index equal to the token number: 0 zero, 1 one, 2 two, 3 three, 4 four, 5..10 categories 1..6, 11 end-of-block (stores at 0x001BBB1E, 0x001BBB35, 0x001BBB5D, 0x001BBB7B, 0x001BBB8F, 0x001BBBB7, 0x001BBBCB, 0x001BBBF3, 0x001BBC07, 0x001BBC25, 0x001BBC3B and 0x001BBB05). Because of the per-step truncation, weights depend on the order of multiplication, the order is root to leaf.
