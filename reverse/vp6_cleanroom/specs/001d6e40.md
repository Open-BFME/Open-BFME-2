# FilterBlock1d_h_mmxa (alternate scheduling | unreferenced)

name: FilterBlock1d_h_mmxa (alternate scheduling | unreferenced)
rva: 0x001D6E40
size: 211
ret_site: 0x001D6F12
convention: cdecl, 7 stack args, caller cleans
args: source pointer (bytes) | output pointer (bytes) | source pixels per line (uint) | pixel step (uint, unused in retail) | output height (uint) | output width (uint, used as the output row pitch) | filter taps pointer (int16)
returns: none
callees: none
tables: 0x00DB81A0 eight 16-bit 64 (rounding)
fields: none

## Behaviour

Four-tap (bicubic) one-dimensional filter producing an 8-pixel-wide block of 'output height' rows. The taps pointer addresses four groups of eight identical int16 weights at byte offsets 0, 16, 32 and 48 (loaded at the entry sequence), the four weights apply, in order, to the sample one position before the output position, the sample at the position, the one after and the one two after. For each output pixel the four weighted samples are summed in 16-bit lanes, the rounding constant 64 is added (saturating add from the table at 0x00DB81A0) and the sum is arithmetically shifted right 7 (the shift-right-7 sites of the body), the result is packed to a byte with unsigned saturation. Horizontal, same contract and results as 0x001D6C90, a differently scheduled alternate that nothing in retail references. Source rows advance by 'source pixels per line', output rows advance by 'output width' bytes, exactly 8 pixels per row are produced regardless of 'output width'. The 'pixel step' argument is not read in retail. No MMX state clear is executed by this routine: it leaves the MMX register state in use on return (the separately installed clear-state routine at 0x001D7620 is the caller's cleanup).
