## Behaviour

Notation used below: inputs of a 1-D transform are in0..in7, its outputs out0..out7, intermediate terms are named by role, multiplier constants by their retail value (M[c](v) = floor(v x c / 65536), see the multiplier notation paragraph), sat() = clamp to -32768..32767, wrap() = modulo 65536.
Generic reduced inverse DCT for blocks with at most the first ten transmission coefficients. Calls 0x001D65A0 with (quantiser matrix, input, local block): that helper zero-fills local entries 0..31, reads and multiplies ELEVEN input/quantiser pairs (transmission positions 0..10) and stores them at natural raster positions 0, 1, 8, 16, 9, 2, 3, 10, 17, 24 and 32, leaving local entries 33..63 untouched. The eleventh product (raster 32 = row 4, column 0) is written but never read by this routine, and local entries 33..63 are never read either, so the transform result depends only on transmission positions 0..9, a non-zero eleventh coefficient is silently ignored (it is still read from the input). First pass over natural rows 0..3 only (0x001D667E onward): a row whose entries 0..3 are all zero is left as is, otherwise the reduced transform (inputs in0..in3 = columns 0..3, columns 4..7 taken as zero) is applied and the eight results stored back truncated to 16 bits. Second pass over all eight natural columns using rows 0..3 as in0..in3 (rows 4..7 taken as zero): a column whose four inputs are all zero produces eight zero outputs, otherwise the reduced transform with the rounding 8 and arithmetic shift right 4, stored as int16 at output index 8 x row + column.

Arithmetic of this scalar routine (its own instruction sites are cited): the first pass works on the 32-bit dequantised products delivered by the helper (quantised value times quantiser entry as a signed 32-bit product), not on 16-bit coefficients. Every multiplication by a transform constant is a signed 32-bit multiply whose LOW 32 bits are kept and then arithmetically shifted right by 16 (0x001D66A1-0x001D66B5 followed by the shifts from 0x001D66BB), written below as M32[c](v): it equals floor(v x c / 65536) only while the full product fits in 32 bits, i.e. while the magnitude of v is below about 33411 for the constant 64277 (proportionally larger bounds for the smaller constants), beyond that the product wraps modulo 2^32 before the shift. Sums and differences are 32-bit (they cannot overflow for inputs in that domain). Each first-pass result is stored truncated to its low 16 bits (16 word stores in the body) and sign-extended when the second pass reads it (0x001D6735-0x001D676A). The second-pass rounding is 8 added before the final arithmetic shift right 4. The value contract is therefore the one given for the reduced routine 0x001D3F30 with every sat() and wrap() read as 32-bit arithmetic, every M[c] read as M32[c], and the first-pass outputs reduced modulo 65536 to the signed 16-bit range.

Check vectors: the DC, (0,1), (1,0) and five-coefficient vectors listed for 0x001D35E0 apply unchanged (no boundary is reached, quantiser entries 1). Discriminating case for the 32-bit multiply: coefficient 30000 at natural (0,1), quantiser entries all 2, everything else zero (dequantised value 60000, whose product with 64277 exceeds 2^31): every output row is -296, 157, -575, 517, -517, 575, -157, 296, whereas an exact-arithmetic multiplier would give -296, -692, -1423, 517, -517, 1423, 692, 296. The saturation vectors of the SIMD routines do not apply.

Reduced value contract (exact arithmetic): oddSum17 = M[64277](in1), oddDiff17 = M[12785](in1), oddSum35 = M[54491](in3), oddDiff35 = -(M[36410](in3)), rotEven = M[46341](in0) used as both even terms, pairSum26 = M[60547](in2), pairDiff26 = M[25080](in2), and the second stage and outputs as listed for 0x001D3F30 with 32-bit sums and M32 multipliers.
