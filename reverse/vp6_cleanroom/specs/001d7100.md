# FilterBlock2dBil_mmx

name: FilterBlock2dBil_mmx
rva: 0x001D7100
size: 254
ret_site: 0x001D71FD
convention: cdecl, 5 stack args, caller cleans
args: source pointer (bytes) | output pointer (bytes, 8x8, pitch 8) | source pixels per line (uint) | horizontal taps (int16 pointer) | vertical taps (int16 pointer)
returns: none
callees: none
tables: 0x00DB81A0 eight 16-bit 64 (rounding)
fields: none

## Behaviour

Separable bilinear 2-D filter producing an 8x8 byte block at the output pointer (row pitch 8). Each of the two taps pointers addresses two groups of eight identical int16 weights (byte offsets 0 and 16): for the horizontal pair the first weight applies to a sample and the second to its right neighbour, for the vertical pair the first applies to a row and the second to the row below. First, nine source rows (the row at the pointer and the eight below, stride 'source pixels per line') are filtered horizontally: each sample and its right neighbour are weighted, summed in 16-bit lanes, 64 added (rounding table listed, e.g. 0x001D714C) and shifted right 7 (0x001D7153), and the result rounded to a byte with unsigned saturation. Then consecutive pairs of filtered rows are combined vertically in the same way (weight, sum, add 64, shift right 7, saturate) producing the eight output rows. The MMX implementation keeps the previous filtered row in registers (two four-lane halves), so the intermediate rounding to 8 bits happens in-register, the results equal the two-pass description. No MMX state clear is executed by this routine: it leaves the MMX register state in use on return (the separately installed clear-state routine at 0x001D7620 is the caller's cleanup).
