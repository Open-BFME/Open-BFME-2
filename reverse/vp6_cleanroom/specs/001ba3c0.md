Behaviour:
Resamples a line of bytes by linear interpolation at a rational rate: every (destination scale) output samples correspond to (source scale) input samples. Output number n (n from 0 below the output count, stored at destination plus n times the destination step) lies at fractional source position n times source scale divided by destination scale. It is formed from the two input samples that bracket that position (the one at or before it and the next one, one source step apart): the earlier sample is weighted by (destination scale minus the fractional remainder), the later by the fractional remainder, half of the destination scale is added, and the total is divided by the destination scale as an unsigned integer (division at 0x001BA416). The fractional remainder is the position's remainder modulo the destination scale, except that a remainder exactly equal to the destination scale is kept (so the weight of the earlier sample becomes 0) rather than advancing to the next pair (the advance test at 0x001BA427 advances only while the remainder exceeds the scale). Outputs are stored as bytes (low 8 bits). The destination scale must be non-zero (it is the divisor), the source and destination steps are byte distances added to the pointers (ascending addresses), and all arithmetic is unsigned 32-bit with wrap-around. The weighted sums fit only while the destination scale is below 2 to the 23rd. The remainder accumulator is advanced by a wrapping 32-bit addition of the source scale (0x001BA423) before the comparison with the destination scale (0x001BA427), and the remainder is at most the destination scale before each addition, so the rational-position description and the closed form below are exact only when the source scale plus the destination scale is below 2 to the 32nd. When that bound is violated an addition can wrap and the advances it would have caused do not happen (for example a source scale of 4294967295 with destination scale 8388607 and two outputs performs 512 advances in total, reading through source offset 513, because the second addition wraps). The highest-offset statement below is an allocation requirement only when the source pointer plus that offset does not wrap around the address space. The output count may be 0, in which case nothing is written. A source scale of 0 is accepted: no advance ever happens, every output is the first source sample (zero remainder gives the earlier sample the full weight), and only source offsets 0 and one step are read. Read footprint, which is larger than the samples that contribute: the first two samples (source offsets 0 and one step) are read unconditionally before the count is examined (0x001BA3D8, 0x001BA3DC). After every output is stored, including the last one, the bracketing pair is advanced one step at a time while the accumulated remainder exceeds the destination scale, and each advance reads the new pair (0x001BA430, 0x001BA432), so when the source scale exceeds the destination scale every skipped pair is read as well. For a positive source scale within that no-wrap bound, after the last of c outputs (c at least 1) the number of advances performed in total is the ceiling of (c times source scale divided by destination scale) minus 1, so the highest source offset read is that count plus 1, times the source step. Example: source step 1, source scale 5, destination scale 1, one output: byte offsets 0 and 1 are read, the single output at position 0 is stored, and then offsets 1..5 are read in overlapping pairs although none of them contributes to an output. The source length argument is not used.
