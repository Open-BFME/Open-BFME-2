# IDct10 clean-room scalar reconstruction

Target 0x001D6660 has a complete 1529-byte cdecl three-pointer body through RET at 0x001D6C58. The approved specs and retail disassembly establish signed-short transmission inputs and quantisers, a local 64-int block, four reduced row transforms and eight reduced columns, and signed-short raster output. The only native callee is actual dequant_slow10 at 0x001D65A0, already rowed as Rva009C5CA0 in Rva009C5CA0FixedPoint.cpp. No decoder source was read, fetched, searched or copied.

The bank is ordinary C++. An unsigned low-32-bit multiply followed by signed conversion and arithmetic shift preserves retail overflow; first-pass outputs truncate to signed short and remain int32 in the local block. The row loop is naturally unrolled by VC7.1. The second pass uses a countdown and increments real column/output pointers. The spec's phrase “16 word stores” is not taken as an instruction claim: retail actually sign-extends each truncated result and writes an int32 local slot.

At frozen BFME2 76dd5d54ee3d52f5c6f1918bf4eef8947970e417, private MSVC7.1 /O2 /G6 /DNDEBUG /MD emitted 1518 bytes versus native 1529, with every relocation resolved to the genuine dequant provider. Only 207 bytes agree at their original offsets (score 207/1529 = 0.135383); matching subsequences total 986 but do not establish byte proof. The same 0x118 stack allocation, row input/OR order and four unrolled row blocks are present. Arithmetic scheduling, temporary spills, allocation, output-store order and one compiler alignment instruction still differ. No matched row, pin, source file or LINK gain is asserted.

Private controls tried direct/scoped input access, explicit versus naturally unrolled four-row loops, countdown columns, natural output pointer origin and raster/pair store order, butterfly staging, source-level product ordering, macro versus forceinline helpers, /O1 and /O2 /G5-/G7. The best reconstruction improved from 1491/515 matching subsequence bytes to 1518/986; the last bounded forms made no further progress. No asm, __emit, volatile, register forcing, aliases or emission anchors were added.

A bounded instruction interpreter executed both complete compiled and retail transforms for 157 cases, including the approved DC/axis vectors, five-coefficient input, ignored eleventh coefficient, 150 deterministic random signed-16 input/quantiser sets, and the discriminating 60000 product-wrap vector. All 64 output words agreed. The real dequant call was substituted by its separately reviewed helper contract, identically for both streams; this validates the scalar transform behavior under that contract, not a full decoder execution or byte-match gate. Raw bytes, exact compiler invocation, frozen input hashes and scope limits are in verification.json. The private interpreter and object trials remain ignored under build/seat3/idct10.

This partial evidence is not a conversion. A future worker must reproduce current input currency and reach the complete native extent, then use normal byte, identity, provider/consumer linking and publication checks.
