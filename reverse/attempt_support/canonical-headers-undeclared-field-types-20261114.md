# 125 canonical headers name a type in a field that they never declare

`header_adopt_lane.py adopt --class Rva002C9B80Owner` fails on all six queued
units, and not because of the units. The generated header does not compile.

## The instance

    python3 tools/header_adopt_lane.py adopt --class Rva002C9B80Owner \
      --header Code/GameEngine/Include/GameLogic/Module/Rva002C9B80Owner.h --apply <6 units>

    FAIL …/HordeContainIface11CSlots.cpp:
      …\Include\GameLogic\Module\Rva002C9B80Owner.h(13):
      error C2143: syntax error : missing ';' before '*'
    FAIL …/PathfinderCheckChangeLayers.cpp (and 4 more):
      C2501: 'Rva002C9B80Owner::BfmeRangedWeaponTemplate' : missing storage-class or type specifiers
      C2501: 'Rva002C9B80Owner::m_m04' : missing storage-class or type specifiers

The committed header (tracked, unmodified) declares the types its **method
signatures** name and not the type a **field** names:

    struct Coord3D;        // from isWithinAttackRange's parameters
    class Object;          //  ditto

    class Rva002C9B80Owner {
    public:
        void *m_00;
        BfmeRangedWeaponTemplate *m_m04;      // never declared, never included
        bool isWithinAttackRange(Object *, const Coord3D *, …);
        …
    };

`BfmeRangedWeaponTemplate` has no forward declaration and no `#include`, so
line 13 is a syntax error and every unit that includes the header fails.

The contract is not at fault: `size 8` with 11 of 12 views agreeing, two
fields, `retail_access` reaching exactly 8, empty `queue`. This is purely the
header the generator wrote.

Examples: `BehaviorModuleBase.h` (`ModuleData`, `Object`),

`ChecklistSelectNode.h` (`Rva0057AD26`).

`BehaviorModuleBase.h` is the clearest: a canonical header for a base class
hundreds of modules derive from, declaring `const ModuleData *m_moduleData;`
and `Object *m_object;` with neither type declared and no include at all.

## Where it is

`generate()` (`tools/header_adopt_lane.py:4253`) writes the guard, then
`nested_includes(contract, header, slots)` (line 4275), then the class body.
`nested_includes` (line 4013) collects only:

- the contract's **bases**,
- fields whose `kind` starts `"S:"` — struct members held **by value**,
- types named in **slot declarations**, when the variant is `+includes`.

A pointer field's type is in none of those sets, so nothing declares it. The
docstring says as much — it is about "member aggregates", i.e. by-value members
whose layout the header needs. A pointer field needs only a declaration, which
is cheaper than an include, and it gets neither.

(The `struct Coord3D;` / `class Object;` lines in the emitted header do not come
from `nested_includes`, which only ever emits `#include`. I did not find the
code that writes them, so the fix may be to extend that emitter rather than
`nested_includes`; whichever it is, it is reading parameter types and not field
types.)

## Not fixed here

This is a one-line-ish change in a generator whose output is 1,377 committed
headers, and regenerating them is a separate decision with its own blast
radius: `header_adopt_lane.py` is gate code, so the fix needs a regression test
and a `Verifier-Change:` trailer, and a seat should not quietly rewrite a
tenth of the canonical headers alongside it. Recorded rather than worked
around, per AGENTS.md.

The repair is to add, for every pointer field whose type is a bare identifier,
either the registered header (when `registered()` knows it) or a forward
declaration with the type's own class-key. The key matters: declaring
`class X;` for a `struct X` is a VC7.1 warning and an inconsistency the
adoption's own key checks would then trip over.

## Reproducing

    python3 tools/header_adopt_lane.py adopt --class Rva002C9B80Owner \
      --header Code/GameEngine/Include/GameLogic/Module/Rva002C9B80Owner.h \
      --apply Code/GameEngine/Source/GameLogic/Object/Contain/HordeContainIface11CSlots.cpp

The 125 come from scanning every tracked `*.h` carrying the generator banner
for a field line `TYPE *name;` (allowing `const`/`volatile`) whose `TYPE` the
file neither forward-declares, defines, typedefs, nor supplies through an
`#include` whose stem matches.
