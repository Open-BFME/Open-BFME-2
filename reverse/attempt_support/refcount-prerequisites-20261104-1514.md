# RefCountClass canonical-header prerequisites

Twenty independent sources were prepared with native claims, prior attempts,
before objects and compiler layouts. Six are admitted separately. Every failed
trial is restored to its original bytes and passes its native restore build;
no rejected source or native verifier change is retained in Code/.

## Shared lifetime-provider boundary

Five trials preserve an existing in-class Delete_This body as out-of-class
inline after the canonical header. Frozen-source validation correctly refuses
the resulting unowned RefCountClass::Delete_This definition. The canonical
header declares that method but does not provide its implementation. The native
existing20B slot body at6CE57 is rowed as BfmeDynamicVBRefCount::DeleteThis.
Its original complete register/flags=0 deleting-destructor call and operator
delete body was prepared unchanged under the header's member, only in build/.
rename.py function --to-class RefCountClass --new Delete_This --dry-run refuses:
other tables are classified as unrelated (Rva006DD51/W3DDynamicLight,
W3DShroudMaterialPassClass, RenderingMethodDelegate). This is absence of the
required inheritance/identity proof, not proof those classes are actually
unrelated at runtime. No alias, pin, invented identity or duplicate row is added.

MaterialInfoCopyCtor's private safety check also sees unrelated Count() calls
after removing the old Count field declaration. No token is blindly renamed;
the same inline-lifetime prerequisite would still need resolving there.

## Consumer context boundaries

Five old opaque Release_Ref declarations call the native outlined provider.
The header's visible body inlines a decrement/dispatch and changes the complete
retail caller/EH shape. These do not qualify merely because the operation is
semantically similar. They need a supported context preserving the outlined
call, with provider/consumer verification and no ad hoc import/pin.

TexBufferClassDtor acquires virtual BfmeOwnVVE teardown through the complete
base and references ??1BfmeOwnVVE@@UAE@XZ instead of its current nonvirtual
owner. Reconcile target inheritance and that provider before adopting the
canonical base; the prior four-byte vptr projection proves no complete extent.
W3DHordeModelDrawProcessGroup changes its native body; the old one-slot base
versus the canonical inherited deleting slot is a concrete layout lead, not a
completed or universally established diagnosis. Preserve the full logged diff.

Rva0015b110Cluster's four old caller bodies match after normalizing the private
AddRef/Release/Delete APIs, but its complete emitted helper set changes:
AddRef and Release disappear, Add_Ref appears. Whole-object closure is not
established by those four retained callers, so the original is kept.

RenderObjClass claims were refused twice; its private views (including the
previous RTS3DScene case) are skipped. PartitionFilter's class claim was also
refused; the one acquired header scope was released without editing it.

No failed trial is solved work or new authored coverage. All candidate patches,
before/restored objects, dependency/layout/code comparisons and native refusals
are preserved under this run. No shared header, ledger, alias, pin, baseline,
compiler option or existing naming record is changed by these investigations.
