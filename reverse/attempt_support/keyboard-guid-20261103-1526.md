# Keyboard format: adopt the SDK GUID tag and definition

The native approved two-source keyboard merge first fails inside the format
header: `struct GUID;` conflicts with windows.h's SDK typedef and VC7.1
reports C1001 there. The pinned toolchain's PlatformSDK/guiddef.h independently
defines GUID as `typedef struct _GUID ... GUID`, with the same16B field layout.
Use that compatible tag/typedef in the shared forward view; the data producer
includes the actual SDK header instead of its private GUID body. Its native
platformsdk marker supplies that SDK include directory; optimization/ABI
switches and all initializers remain unchanged. There is no macro alias,
new global name, pin, forwarding wrapper or verifier exception.

The format producer's16B GUID and4096B/256-record table retain every initialized
byte and all256 GUID relocations under the normal data gate. The existing
openKeyboard188B function and its3 data rows/56B also pass. Both objects retain
all non-debug sections and all existing code/relocations exactly. Source-level
external identities stay C-linkage GUID_Key/table and the existing descriptor;
the SDK tag adoption changes no ledger spelling or data ownership.

The owning Microsoft-header audit removes the former conflicting GUID:mangle
view key and preserves all unrelated queue records. Queue records for this
producer before/after: 1 -> 0.
The ordinary header dependency hook must gate every affected source in this
commit; no manual dependent list replaces it. The native merge remains a
separate step after this verified shared-header prerequisite.

No new native coverage, memory, crash, input-runtime or full linking gain.
