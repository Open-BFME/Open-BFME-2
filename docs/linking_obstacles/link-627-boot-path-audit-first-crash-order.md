### LINK-627: Boot-path audit: what the rebuilt game constructs before the menu, ranked by first crash

Status: Open (partly repaired). Updated: 2026-11-07 (seat halilkkaya-lk55); base `340595af5e5`, census index
`eb08bc29f1`, real link `bbb1979380` (2026-11-07 02:48 UTC: 234 unresolved, 4,421 tables and 605 initializers bridged).

Evidence / affected units: [boot-path inventory](../../reverse/attempt_support/boot-path-audit-20261107-lk55.tsv)
(one row per defective vptr store reached from the boot anchors: anchor, tier, function, slot, retail table, our symbol,
defect, kept/retail slots, the bridge's verdict with the committed and with a regenerated data ledger, kept source) and
its [walker](../../reverse/attempt_support/boot-path-audit-20261107-lk55.py). Related: LINK-625 (zero placeholders),
LINK-514 (kept `??_7` copies), LINK-557 (MessageStream), the first image report (bridge design).

**Problem.** The rebuilt game links in diagnostic mode and crashes during startup; no crash receipt is visible to seats.
A virtual call crashes when the object's vptr is a zero placeholder (the bridge cannot see a store that names no `??_7`),
or when the kept `??_7` copy is shorter than retail's or holds `__purecall` and the real link's bridge did not replace
it. This entry lists those defects in the order boot meets them.

**Method (reusable).**
- Walk retail's call graph (capstone over the retail image, ledger rows as function extents) from WinMain, then from
  each call GameEngine::init (0x0022E2E4) makes, in instruction order; its `call [reg+disp]` sites are read as
  Win32GameEngine's factory slots (createGameClient, createModuleFactory, ...). Direct edges: E8 calls, outward E9
  jumps, code immediates, and code words inside the data-ledger rows the code references (the INI block and FieldParse
  tables). A constructor's vptr store adds its table's slots one tier further (at most two).
- Every vptr store found (`mov dword [m], imm32`, imm32 starting a run of `.text` words in `.rdata`) is paired with our
  object's relocation at the same offset. A non-`??_7` symbol in lk49's zero inventory is a ZERO vptr. A `??_7` name
  gets the kept copy's verdict from LINK-514's survey (rerun on this tree) and the real link's bridge decision.
- An offline A/B of the bridge's plan (`vtable_bridge.plan` over the exit link's own inputs, no link): the committed
  `reverse/data_ledger.csv` against one regenerated by `tools/data_ledger.py --out`.
- Limits: reachability in boot order, not a trace. Tier-1 rows under an anchor can belong to a later phase (the CRC
  writer's virtuals reach Object::Object); anchor numbers below are GameEngine::init call indices.

**Finding 1 (tooling; the largest lever).** The bridge only bridges tables that the committed data ledger lists as
`kind=vtable` (`vtable_bridge.table_rows`), and that ledger is stale: `python3 tools/data_ledger.py --check` fails,
21,902 rows against 34,436 regenerated. The real link discovered 604 bindings (349 retail tables) from matched
vptr stores that it then skipped as `unindexed`. They include every engine-init subsystem table below. The offline
A/B at this base:

| plan | tables | retail tables | slots | refused | unindexed bindings | names bridged |
|---|---:|---:|---:|---:|---:|---:|
| committed ledger | 4,417 | 3,049 | 63,950 | 212 | 616 | 4,518 |
| regenerated ledger | 4,715 | 3,339 | 61,230 | 232 | 200 | 4,839 (+457, -136) |

The 136 lost names are the catch: 128 become `strong-definition` refusals, because the regenerated ledger also names
hand-built strong arrays bound at the same addresses (`_g_productPrimaryTable`/`_g_productSnapshotTable`/
`_g_productInterface10Table` at InGameUI's 0x00BC7A88/78/64, the BehaviorModuleInterface fold 0x00BEFF90 with 88
names, `_g_weaponStoreTable` 0x00C02114, `_g_aptValueBaseTable` 0x00CEA228), and the bridge refuses a whole address
when any name there has a strong definition (`tools/vtable_bridge.py` 494-497). 166 bridged names also get shorter, correct
extents (CreateModule's BehaviorModuleInterface 59 -> 47). Hatch counts are identical with either ledger
(`hatch_counters.py --report`). Needed, in order: make the strong-definition refusal per name (the strong name keeps its
own definition; the COMDAT names at that address can still get a select-any copy), then regenerate and commit the
ledger (`python3 tools/data_ledger.py`, protected path, `Verifier-Change`). Not done here: it is the Link tooling lane's
change to make, and the refresh alone would trade InGameUI's tables for the subsystems'.
